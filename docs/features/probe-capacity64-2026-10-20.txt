64-capture reflection storage and authoring - 2026-10-20

Implementation
Automatic capture budget, public authoring quota and GPU table now support64.
The screen-space filter uses two32bit mask words across its existing64threads;
slot order, oriented containment, priorities, roughness and feathering remain.
The private GPU header is8208bytes. Public record/request layouts and extension
version are unchanged; increasing the authoring quota is additive.
Editor export and the Source sidecar decoder support64volumes with the matching
SDK/runtime. Stale SDK quotas fail the adapter interoperability test.

Disk headers use whole32record blocks selected by the preceding capture count,
independent of GPU table capacity. Up-to32capture payloads keep their historical
bytes/layout;33..64use two blocks. Existing cache keys remain valid at unchanged
settings. Larger GPU-header content hashes can differ without a rebake; raw
capture inputs/radiance and visible output remain authoritative comparisons.
Changing the requested budget creates a distinct cache entry and can require a
fresh bake. Old entries are retained.

Automatic selection observes the device's complete header/mip storage footprint.
For example, a128MiB storage range fits63size128captures, not64. Authored requests
which exceed device storage are rejected before tracing rather than silently
truncating; the existing valid set is retained when editing at unchanged settings.
The geometry audit stays capped at160candidates and128primary fit sites. Larger
capture counts do not expand that audit cap.

Default remains16. UI/config accept rtx.native.forward.reflectionProbes up to64.
Water/viewmodel fragment paths retain their contiguous walk; larger global sets
still need live performance checks. No lightmap page, density or PBR policy change.
