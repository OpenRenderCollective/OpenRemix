Forward+ draw-constant CPU packing (2026-10-20)

Changes
normalMatrix now handles an exact identity linear transform and finite translation
directly, preserving the complete inverse transpose. Other transforms still use
the existing pivoted inverse, including singular-transform rejection. No inverse
approximation, tolerance-based classification or general affine rewrite.

Byte blend-factor RGB conversion uses a process-local immutable256entryfloat
table (1KiB), initialized from the original sRGB formula. Alpha remains linear.
This removes repeated exponentiation while preserving all256RGB input values.
The272byte DrawData layout, material replacement path, shaders, bake identities
and cache formats are unchanged. No renderer switch or extra mutable cache.

Verification
New CPU tests compare343translation combinations (including signed zero, large
coordinates and float maximum), one-component scale/shear/projective variations,
rotation, singular rejection, and permutations covering all256values in all four
colour-factor channels. Equality is exact float-value equality; signed zero has
its normal arithmetic equality. GPU lighting/MSAA, skinned/transient frame-slot
geometry and viewmodel environment tests also pass before the final byte-table
addition; the final combined check is recorded separately below.

Expected scale
The saved time is tens of nanoseconds per packet in these controls. This is a
small CPU improvement, not a solution to the multi-millisecond c1a0 setup/record
cost or reported worst-case performance. No live-frame improvement is claimed.

Cubemap follow-up
The existing one-sided projection-confidence score deliberately tolerates nearer
props. It alone cannot justify growing projection boxes to enclose more room
geometry. Receiver visibility and structural projection error still need separate
validation. No new cubemap fitting or influence behavior is introduced here.
Continue that work and the remaining CPU/frame, shadow, bake-time and editor
gates; the full project remains incomplete.
